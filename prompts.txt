## What has to change vs. Cloud Run

Current setup (from cloud-run.sh and Dockerfile): Quarkus 3.9.2 / Java 21 + Angular (Quinoa), PostgreSQL via **Cloud SQL socket factory**, secrets in **Secret Manager**, image built by **Cloud Build**, external **Gemini API** egress.

| # | Task | What changes | Effort |
|---|------|--------------|--------|
| 1 | **Database** | Run PostgreSQL 16 locally (container or native). The app already falls back to plain TCP — just set `DB_JDBC_URL`/`DB_HOST`/`DB_USER`/`DB_PASSWORD`. Cloud SQL socket factory becomes unused (can stay). Flyway creates the schema at startup. | Low |
| 2 | **Secrets** | Replace Secret Manager with env vars / an `.env` file (`GOOGLE_API_KEY`, `DB_PASSWORD`, `AUTH_USERS`). | Low |
| 3 | **Build & run** | `docker build` + `docker run` on the VM (or a small `docker-compose.yml` with app + postgres). The multi-stage build needs outbound internet for Maven/npm. | Low–Med |
| 4 | **Gemini egress** ⚠️ | Request **outbound HTTPS (443) to `generativelanguage.googleapis.com`**. Without this, all AI features fail. | Low (but a blocker if missed) |
| 5 | **HTTPS / external** | Serve HTTP on 8080, then ask Gersist for the reverse proxy. Set `AUTH_JWT_ISSUER` and `CORS_ORIGINS` to the public hostname. SPA+API are same-origin, so the proxy is simple. | Low |
| 6 | **Process mgmt & backups** | `--restart unless-stopped` (or systemd), plus `pg_dump` cron — you now own backups (no managed DB). | Med |

No Java/Angular code changes are strictly required; the JDBC fallback at application.properties already supports a local PostgreSQL.
